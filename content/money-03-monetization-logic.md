«Донатные помойки» — разговорное название игр, где игровой цикл подчинён продаже: прогресс искусственно замедлен, а покупка снимает «боль». Они часто зарабатывают много в краткосрочном периоде, но имеют цену: репутация, жалобы родителей, риск санкций Roblox/регуляторов, быстрое выгорание аудитории. Ниже — **как это устроено** (чтобы вы понимали механику и могли строить честную версию) и **что делать иначе**.

:::note Позиция справочника
Мы описываем механики и их последствия. Цель — научить делать **прибыльные игры, которые не обманывают игроков** (особенно детей) и не нарушают правила. Это и этично, и выгодно в долгосрочной перспективе: удержание, отзывы и стрим-контент создают устойчивый рост.
:::

## Каталог механик

| Механика | Как работает | Что чувствует игрок | Риски | Честнее |
|---|---|---|---|---|
| **Множители x2/x3** (деньги, опыт, скорость) | постоянный бонус за пасс | «буду быстрее» | дисбаланс PvP, ощущение «платного забега» | косметика; множитель только в PvE; бесплатный временный буст за активность |
| **Авто-функции** (авто-сбор, авто-клик) | убирают рутину | удобство | если без пасса игра невыносима — «стена» | разрешить базовое «авто» бесплатно, платное — комфорт |
| **VIP-зона/статус** | эксклюзивная зона, цвет ника | престиж | «давление социума» | честный статус, понятная польза |
| **Питомцы/предметы за Robux** | сильнее/красивее | коллекционирование | баланс | косметические «скины» и мета без влияния на силу |
| **Рандом за Robux (яйца/сундуки)** | случайный результат | азарт/надежда | **регулируется**, зависимость, жалобы | прозрачные шансы, «pity», гарантированные варианты, лимиты |
| **Удача (luck boost)** | повышает редкие шансы | «так выпадет!» | это тоже модификатор шансов — **регулируется** | показывать итоговые вероятности |
| **Ускорение таймера** | пропуск ожидания | нетерпение | давление на детей | бесплатные способы ускорить, мягкие напоминания без «паники» |
| **Дефицит/ограниченное время** | «только сегодня», «осталось 2 места» | страх упустить | ложный дефицит = обман | реальные ивенты с понятным сроком |
| **Социальное доказательство** | «Игрок X только что купил…» | «все покупают» | манипуляция | прозрачные уведомления о достижениях, а не о тратах |
| **Подарки между игроками** | покупка для друга | социальная связь | мошенничество, скам | защита обменов, лимиты, подтверждения |
| **Подписка** | регулярные бонусы | выгода «сэкономить» | подписка по инерции | ясные условия, пользы хватает без ощущения «обязательства» |
| **Лимитированные предметы** | эксклюзив по времени | статус | FOMO | периодические «возвраты» и честные сроки |
| **Battle pass / сезонный пропуск** | награды за прогресс | цель на месяц | «долг» перед пассом | бесплатная ветка + платная дополнительная, без «пропал — потерял» |

## Психология за механиками (чтобы понимать, а не манипулировать)

1. **Трение → облегчение.** Создайте дискомфорт (ожидание, скука), затем продайте облегчение. Честная версия: «приятный цикл + платные удобства и красота».
2. **Вариативное вознаграждение.** Непредсказуемая награда (рандом) цепляет сильнее предсказуемой. Опасная зона: детская аудитория.
3. **Потеря и дефицит.** Страх упустить сильнее радости получить. Ложный дефицит нечестен.
4. **Социальное сравнение.** «У него есть, у меня нет». Честная версия: показывайте *достижения*, а не *траты*.
5. **Якорение цен.** Показывают дорогое и «выгодное» рядом. Честно: ясные цены и прозрачная ценность.
6. **Эффект «уже вложился» (sunk cost).** После вложений игрок продолжает. Не используйте для давления.

## Масштаб проблемы и регулирование

- Аудитория Roblox — в значительной степени **дети и подростки**; к механикам, связанным с оплатой и случайностью, предъявляются повышенные требования законов о защите потребителей и политик платформы.
- Roblox вводит и ужесточает правила по **платным случайным предметам** (раскрытие вероятностей, включая усилители шансов) и по **честности** описаний покупок; нарушающие игры теряют показы или удаляются. Подробности — [[money-04-ethics-compliance]].
- Поддержка в Roblox, родительский контроль, возможность возвратов — реальность: «агрессивная» монетизация повышает риск жалоб.

## Как строить прибыльную игру честно

### 1. Начните с цикла, который приятен БЕЗ покупок
Если игра не нравится бесплатно — платить не будут (или будут, но уйдут и оставят дизлайки).

### 2. Продавайте **время, удобство, красоту, статус** — не «победу»
- Время: ускорители с бесплатной альтернативой.
- Удобство: авто-функции, дополнительные слоты, быстрые телепорты.
- Красота: скины, эффекты, питомцы-косметика.
- Статус: титулы, рамки, цвета, места.

### 3. Предложения вовремя и по контексту
Показывайте покупку, когда игрок **понимает ценность**: после первого ребёрта — «авто-ребёрт», при полном инвентаре — «+слоты». Не «заваливайте» окнами при входе.

### 4. Прозрачность
Цена, шансы, что даёт покупка, срок действия — в одном месте и простыми словами.

### 5. Мягкие паттерны вместо тёмных
| Тёмный паттерн | Альтернатива |
|---|---|
| Таймер «закроется через 10 минут!» без реальной причины | Реальные сезонные события с датой |
| Кнопка «нет, я не хочу прогрессировать» | Нейтральные «Закрыть» / «Не сейчас» |
| Невозможно закрыть окно | Всегда видимый «крестик» |
| Скрытые шансы, «удача» без цифр | Показывать проценты |
| Подсказки «все покупают» | Показывать «популярный выбор» по реальным данным без давления |
| Затенение бесплатного пути | Бесплатный путь — полноценный |

### 6. Ограничения для защиты игроков
- Лимиты на трату в день/неделю для случайных покупок (в идеале настраиваемые).
- Подтверждение дорогих покупок.
- Информация в настройках: «Как играть без трат».
- Быстрый и вежливый саппорт: форма «Сообщить о проблеме», возврат валюты при баге.

## Антифрод и честность внутри игры

- **Дюпы и эксплойты** уничтожают экономику сильнее, чем что-либо: серверные проверки, идемпотентные покупки, журналирование.
- **Скам при обмене:** подтверждения, окно предпросмотра, задержка, список «замороженных» предметов.
- **Выкуп валюты вне платформы** запрещён — следите, блокируйте, предупреждайте.
- **Боты/ферма аккаунтов:** лимиты на аккаунты-новички, проверка активности.

## Деньги vs доверие: расчёт

Простая модель «жизни» игрока (LTV):

```lua run
-- LTV = ARPDAU * ожидаемое число дней
local function ltv(arpdau, d1, d7, d30)
  -- грубая интерполяция удержания: сумма вероятностей быть в игре в каждый день до 30
  local days = 1
  local function ret(day)
    if day <= 1 then return d1 end
    if day <= 7 then return d1 + (d7 - d1) * (day - 1) / 6 end
    return d7 + (d30 - d7) * math.min(1, (day - 7) / 23)
  end
  for d = 1, 30 do days += ret(d) end
  return arpdau * days, days
end

local aggressive = {ltv(0.05, 0.20, 0.04, 0.01)}   -- высокое ARPDAU, быстро уходят
local friendly   = {ltv(0.03, 0.35, 0.15, 0.07)}   -- ниже ARPDAU, но возвращаются
print(("агрессивная: LTV %.2f, дней %.1f"):format(aggressive[1], aggressive[2]))
print(("дружелюбная: LTV %.2f, дней %.1f"):format(friendly[1], friendly[2]))
```

Игра, которая удерживает игроков и вызывает доверие, часто выигрывает: больше органического трафика (алгоритм любит удержание), лучше отзывы, больше контента от стримеров.

::::task mid Лимит на покупки (чистый Lua)
Напишите `makeSpendLimiter(dailyLimit)` → `try(userId, amount, day)`: разрешает покупку (`true`), если суммарная трата пользователя за этот `day` с учётом `amount` не превысит `dailyLimit`; иначе `false` и трата не учитывается. На новый `day` счётчик обнуляется.

:::starter
```lua
local function makeSpendLimiter(dailyLimit)
end
```
:::
:::test
```lua
local try = makeSpendLimiter(100)
assert(try(1, 60, "d1") == true)
assert(try(1, 50, "d1") == false)
assert(try(1, 40, "d1") == true)
assert(try(2, 100, "d1") == true)
assert(try(1, 100, "d2") == true)
```
:::
:::answer
```lua
local function makeSpendLimiter(dailyLimit)
  local spent = {}
  return function(userId, amount, day)
    local record = spent[userId]
    if not record or record.day ~= day then
      record = {day = day, total = 0}
      spent[userId] = record
    end
    if record.total + amount > dailyLimit then
      return false
    end
    record.total += amount
    return true
  end
end
```
Такая «защита от перетраты» повышает доверие родителей и снижает возвраты.
