## Кто владеет игрой

**Лучшая практика для команды — Roblox Group.** Experience создаётся «в группе»; владелец — группа, а не личный аккаунт. Тогда:
- Права выдаются по ролям (редактирование, публикация, управление монетизацией, выплаты).
- Если человек уходит — его доступ отзывается без потери игры.
- Доход идёт на баланс **группы**, откуда его распределяют.

Роли (пример для двух человек):

| Роль в группе | Права |
|---|---|
| Owner (владелец) | всё, включая выплаты; 2FA обязательна |
| Developer | редактирование и тест; публикация только в Dev |
| Release manager | публикация в Production |

Для Experience настраиваются **Collaborators/Permissions** отдельно от ролей группы — проверьте актуальные настройки в Creator Hub.

## Как делить доход

Варианты:

| Модель | Описание | Плюсы | Минусы |
|---|---|---|---|
| **50/50** | равные доли | просто, мотивирует | не учитывает вклад |
| **По вкладу (60/40)** | доля зависит от роли/объёма работы | честнее | споры об оценке |
| **Ставка + доля** | фикс за работу + % от прибыли | прогнозируемо | нужны начальные деньги |
| **Пул «после расходов»** | сначала покрыть расходы (реклама, ИИ, ассеты), остаток делят | отражает реальную прибыль | нужен учёт |
| **Vesting (получение долей по времени)** | доля «созревает» за 12–24 мес. | защищает от «ушёл через месяц» | сложнее |

Совет для пары: **распределение по условиям до успеха**, письменно. Хорошая точка старта — 50/50 с vesting и пунктом «пересмотр доли через 6 месяцев по фактическому вкладу».

### Групповые выплаты (Group Payouts)

Группа может выплачивать Robux участникам по долям или суммам (настройки *Revenue → Payouts* в группе; есть ограничения по возрасту группы/участников, условия меняются — читайте Help Center и Creator Hub). Далее каждый участник **сам выводит свои Robux** (DevEx) на своём аккаунте и платит налоги по законам своей страны. Это проще, чем делить уже выведенные деньги.

## Что прописать в соглашении (чек-лист)

- [ ] **Цель проекта** и роли
- [ ] **Доли дохода** и формула (что считается «выручкой»: до или после расходов)
- [ ] **Расходы:** кто платит за ИИ-инструменты, рекламу, ассеты; как возмещается
- [ ] **Интеллектуальная собственность:** кому принадлежит код, арт, бренд; право использовать при уходе; лицензия на сделанные ассеты
- [ ] **Лицензии сторонних ассетов** и ИИ-контента (кто проверяет)
- [ ] **Решения:** кто решает по продукту, монетизации, найму; что требует согласия обоих (продажа игры, смена модели монетизации, изменение долей)
- [ ] **Выход участника:** что с долей (выкуп, сохранение процента на N месяцев), передача доступов, период «cool-off»
- [ ] **Конфиденциальность** и запрет на копирование проекта
- [ ] **Споры:** как решаем (переговоры → медиатор → суд/арбитраж; применимое право)
- [ ] **Налоги:** каждый отвечает за свои
- [ ] **Безопасность:** 2FA, управление доступами, порядок резервного копирования

## Налоги и документы (в рамках пары)

- Каждый **сам платит налоги** с полученной суммы по законам своего места жительства.
- Если один из вас оформляет JDG/компанию, а второй — нет, продумайте, как оформляется взаимодействие (например, фактуры B2B между его JDG и вашим, или выплаты через группу напрямую каждому).
- Фиксируйте переводы: дата, сумма, основание.

## Распространённые конфликты и как их избежать

| Конфликт | Причина | Профилактика |
|---|---|---|
| «Я сделал больше» | нет метрики вклада | еженедельный лог задач, пересмотр долей по расписанию |
| «Куда пошли деньги?» | нет учёта расходов | общая таблица доходов/расходов |
| «Кто владеет игрой?» | оформлено на личный аккаунт | группа с самого начала |
| «Я ухожу и забираю свой код» | нет IP-пункта | соглашение + лицензия |
| «Мы не согласны с монетизацией» | разное видение | принцип «тест решает», документ «правил монетизации» |
| Доступ остался у ушедшего | нет процедуры | чек-лист офбординга: роли, ключи API, Discord, GitHub, пароли |

## Офбординг (когда участник уходит)

1. Забрать роли в группе, доступы в Creator Hub.
2. Удалить из GitHub и Discord; перевыпустить секреты (API-ключи), которые он видел.
3. Передать знания (док «как всё устроено»).
4. Закрыть финансовые вопросы по соглашению.

::::task mid Расчёт долей (чистый Lua)
Напишите `splitRevenue(revenue, expenses, shares)`: `shares` — таблица `имя → доля` (сумма долей = 100). Сначала вычесть расходы (но не ниже 0), остаток разделить по долям; вернуть таблицу `имя → сумма`, округлив вниз до 2 знаков.

:::starter
```lua
local function splitRevenue(revenue, expenses, shares)
end
```
:::
:::test
```lua
local r = splitRevenue(1000, 200, {Ann = 60, Bob = 40})
assert(r.Ann == 480 and r.Bob == 320)
local z = splitRevenue(100, 500, {Ann = 50, Bob = 50})
assert(z.Ann == 0 and z.Bob == 0)
local f = splitRevenue(100, 0, {A = 33.33, B = 33.33, C = 33.34})
assert(f.A == 33.33 and f.C == 33.34)
```
:::
:::answer
```lua
local function splitRevenue(revenue, expenses, shares)
  local profit = math.max(0, revenue - expenses)
  local result = {}
  for name, pct in pairs(shares) do
    local amount = profit * pct / 100
    result[name] = math.floor(amount * 100 + 1e-9) / 100
  end
  return result
end
```
:::
