## Платные случайные предметы (Paid Random Items)

Roblox требует от разработчиков раскрывать **реальные вероятности** для предметов, которые игрок получает случайным образом за Robux — напрямую или косвенно (через внутриигровую валюту, которую можно купить за Robux). Суть требований по официальной странице [Paid random items policy](https://create.roblox.com/docs/production/monetization/paid-random-items):

- Нужно перечислить **все возможные исходы** и их **числовые вероятности**.
- Вероятности указываются в **процентах**, сумма всех финальных исходов — ровно **100%**.
- Список можно показывать во всплывающем окне, но значок «(i)» без пояснительного слова — недостаточно.
- Правило действует и для **косвенных покупок**: если игрок покупает семена/яйца, а случайный результат наступает позже («посадил → получил награду»), вероятности нужно показать **до** этого шага.
- «Усилители шансов» (luck boosts, pity и подобные «probability modifier items») тоже подпадают под правило: показывайте влияние на вероятности.
- Правила могут быть усилены в отдельных странах (в связи с местными законами), включая возможность замены случайных покупок гарантированными.

Практика: храните таблицы шансов **в одном модуле** на сервере и используйте один и тот же источник данных и для выпадения, и для отображения в UI — чтобы опубликованное совпадало с реальным.

```lua
-- Shared/EggOdds (ModuleScript): единственный источник правды
return {
  Basic = {
    { Id = "Dog", Chance = 60 },
    { Id = "Cat", Chance = 30 },
    { Id = "Fox", Chance = 10 },
  },
}
-- UI читает тот же список для окна «Шансы»; сервер использует его для выпадения.
```

## Защита детей и подростков

- Не собирайте и не публикуйте **личные данные** (имена, адреса, соцсети, телефоны) — это нарушение правил.
- Весь пользовательский текст (чат, имена питомцев, табло) — через **фильтры Roblox** (`TextService:FilterStringAsync`, `TextChatService`).
- Не делайте **давящих** покупочных механик на детскую аудиторию; избегайте «хитрых» кнопок/таймеров.
- Не поощряйте **внешние платежи и вывод валюты** (обмен Robux на деньги вне платформы запрещён).
- Реагируйте на **жалобы**: форма обратной связи, быстрый возврат при баге.
- Возрастные ограничения контента и общения: заполняйте опросник (Experience Guidelines) честно; некоторые функции (голосовой чат, доступ к «взрослому» контенту) требуют подтверждения возраста.

## Платформенные правила: ключевые темы

| Тема | Кратко |
|---|---|
| **Community Standards** | запрет насилия/домогательств/опасного контента, поведение, контент для разных возрастов |
| **Монетизация** | честное описание покупок, запрет обмана, запрет азартных игр на деньги |
| **Азартные механики** | запрещены ставки/«казино» с реальными деньгами/Robux на вывод; платные случайные предметы — с раскрытием |
| **Авторские права и бренды** | не использовать чужие бренды, музыку, персонажей без прав |
| **Безопасность** | запрет на мошенничество, фишинг, нарушение приватности |
| **Эксплойты** | серверные проверки; запрет на эксплуатацию багов |
| **Ads/промо** | реклама в игре регулируется отдельными правилами |

Ссылки на документы: [Roblox Community Standards](https://en.help.roblox.com/hc/en-us/articles/203313410-Roblox-Community-Standards), раздел **Policies** в [Creator Hub / Docs](https://create.roblox.com/docs). Читайте раз в квартал — политики обновляются.

## Данные игроков и приватность (GDPR и др.)

- Минимизируйте сбор данных: храните только то, что нужно (UserId, игровые данные).
- Не логируйте лишнее персональное.
- Предусмотрите механизм **удаления данных по запросу** (если у вас есть сторонние хранилища); для DataStore — функции удаления/анонимизации.
- В публичных описаниях — честное «что мы храним».

## Авторские права и лицензии ассетов

- Модели, звуки и изображения из **Creator Store** имеют лицензии — проверяйте.
- Не загружайте материалы с чужим логотипом/музыкой.
- ИИ-генерации: проверьте условия сервиса для **коммерческого использования**.
- Не копируйте чужие игры (клоны) один в один: нарушение правил и риск удаления.

::::task mid Проверка шансов с модификатором (чистый Lua)
Напишите `applyLuck(items, luck)`: `items` — массив `{name, chance, rare}` (`rare = true` для редких). Умножьте шанс редких на `luck`, нормализуйте так, чтобы сумма снова была 100, вернуть новый массив `{name, chance}` (округлять не нужно). Это ровно те значения, которые должны показываться игроку при активной «удаче».

:::starter
```lua
local function applyLuck(items, luck)
end
```
:::
:::test
```lua
local items = {
  {name = "Dog", chance = 80, rare = false},
  {name = "Dragon", chance = 20, rare = true},
}
local r = applyLuck(items, 2)
local total = 0
for _, it in ipairs(r) do total += it.chance end
assert(math.abs(total - 100) < 1e-9)
assert(math.abs(r[2].chance - (20 * 2) / (80 + 40) * 100) < 1e-9)
assert(math.abs(r[1].chance - 80 / (80 + 40) * 100) < 1e-9)
```
:::
:::answer
```lua
local function applyLuck(items, luck)
  local weighted, total = {}, 0
  for i, it in ipairs(items) do
    local w = it.chance * (it.rare and luck or 1)
    weighted[i] = w
    total += w
  end
  local result = {}
  for i, it in ipairs(items) do
    result[i] = {name = it.name, chance = weighted[i] / total * 100}
  end
  return result
end
```
:::
