:::note Принцип, а не конкретные названия
Названия моделей меняются, а **классы** остаются: у каждого провайдера есть (1) самая сильная и дорогая модель, (2) «рабочая лошадка» по цене/качеству, (3) быстрая и дешёвая, плюс (4) открытые модели, которые можно запускать у себя. Ниже — как выбирать класс под задачу. Актуальные названия и цены проверяйте у провайдеров (Anthropic, OpenAI, Google, DeepSeek, Alibaba/Qwen, Mistral и др.).
:::

## Четыре класса моделей

| Класс | Идея | Цена | Скорость | Когда брать |
|---|---|---|---|---|
| **S — флагман (reasoning)** | максимум качества, длинные рассуждения | высокая | медленнее | архитектура, сложные баги, безопасность, планирование |
| **A — рабочая лошадка** | хорошее качество за разумные деньги | средняя | быстро | 80% кодинга: модули, рефакторинг, тесты |
| **B — быстрая/дешёвая** | простые задачи, высокий объём | низкая | очень быстро | шаблоны, форматирование, конфиги, переводы, ревью по чек-листу |
| **L — локальная/открытая** | запуск у себя или у дешёвого хостинга | ≈ 0 за токен | зависит от железа | массовая рутина, приватный код, офлайн |

## Таблица «задача → класс»

| Задача | Класс | Комментарий |
|---|---|---|
| Продумать архитектуру игры, схемы данных, экономику | **S** | один раз и качественно; результат сохраните в документ |
| Найти редкий/сложный баг (гонки, репликация, утечки) | **S** → **A** | флагман диагностирует, рабочая модель правит |
| Писать новые модули по ТЗ (Shop, Inventory, Pets) | **A** | основная работа |
| Тесты, документация, комментарии | **A / B** | |
| Форматирование, переименование, простые правки | **B** | или линтер/StyLua, ИИ не нужен |
| Генерация конфигов/таблиц предметов, диалогов, квестов | **B / A** | пакетно, с валидацией схемы |
| Локализация и тексты | **B / A** | |
| Ревью кода по чек-листу безопасности | **A**, спорное — **S** | дайте чек-лист из [[ai-05-no-errors]] |
| Объяснение чужого кода/ошибки из Output | **B / A** | |
| UI-идеи, дизайн-система, названия, описания игры | **A** | + генератор изображений |
| Идеи геймдизайна, анализ метрик | **S / A** | с вашими реальными данными |
| Массовая рутина (1000 файлов, разметка) | **L** или **B** (batch-API) | обычно в 2–10 раз дешевле |
| Работа с большим кодом (>100K токенов контекста) | **A/S с длинным контекстом** + выборочная подгрузка | см. [[ai-04-token-economy]] |

## Нужны ли «все ИИ»?

Для небольшой команды достаточно **2–3 инструментов**:
1. **Агентный кодер** (CLI или в редакторе) на модели класса A — ежедневная работа с файлами.
2. **Чат с моделью класса S** — планирование, сложные баги, разборы архитектуры и «второе мнение».
3. **Генератор ассетов** (изображения/3D/звук) — арт и звук.

Остальное — по необходимости. Чем меньше инструментов, тем меньше хаоса в «источниках правды».

## Роли ИИ в проекте («мини-студия»)

| Роль | Кто/что | Вход | Выход |
|---|---|---|---|
| **Архитектор** | S | описание игры, ограничения | схема модулей, данные, экономика, риски |
| **Программист** | A (агент) | ТЗ на модуль + контекст + правила | код, diff |
| **Ревьюер безопасности** | другая модель (S/A) | diff + чек-лист | список проблем |
| **Тестировщик** | A/B | модуль + контракт | тесты для логики на чистом Luau |
| **Технический писатель** | B | код | README, комментарии |
| **Арт/звук** | генераторы | бриф и референсы | ассеты (проверить лицензию/правила) |
| **Локализатор** | B | таблица строк | переводы |

Ключевая идея: **разные модели для написания и проверки** — вторая модель часто замечает то, что пропустила первая (меньше «слепых пятен»).

## Маршрутизация: самый дешёвый способ экономить

```text
Задача → [ Классификатор правил ]
   ├─ механика (формат/ренейм)      → инструмент (StyLua/регэкспы), без ИИ
   ├─ простая/шаблонная             → класс B
   ├─ обычная разработка            → класс A (агент)
   ├─ сложное/рискованное           → класс S — но только «мозговой штурм/ревью», не печать кода
   └─ массовая                      → L или batch-API
```

Пример: «Добавь систему яиц» →
1. **S** (5–10 мин): «спроектируй модуль: данные, API, события, риски дюпа, схема DataStore» → сохранить `docs/eggs.md`.
2. **A (агент)**: реализует по `docs/eggs.md` + правилам проекта → код + запуск линтеров.
3. **B**: генерирует таблицу `EggConfig` (названия, шансы, описания) с валидатором суммы шансов = 100%.
4. **A/S**: ревью безопасности/дюпа по чек-листу.
5. Вы: проверяете в Studio и на телефоне.

## Что объединять и как

| Связка | Что даёт |
|---|---|
| **Rojo + Git + агент** | код под контролем, ИИ работает с файлами |
| **Агент + MCP Studio** | ИИ видит и правит живую сцену, запускает тест |
| **Агент + линтеры/анализатор в цикле** | ИИ сам видит ошибки (selene, luau-lsp, StyLua) и исправляет — меньше токенов на ваши объяснения |
| **Чат (S) → документ → агент (A)** | дорогие «мозги» один раз, дешёвая реализация много раз |
| **Генератор арта → пайплайн импорта** | иконки/текстуры оптом, единый стиль через промпт-«стайлгайд» |
| **Open Cloud-скрипты** | автопубликация, массовые операции с DataStore, отчёты |
| **Таблицы конфигов (data-driven)** | ИИ добавляет контент (предметы, питомцы), не трогая код |
| **GitHub Actions** | на каждый PR: форматирование, линт, анализ, тесты, сборка `.rbxl` |

## Минимальный «набор денег-безопасности»

Если бюджет ограничен: бесплатный/дешёвый план у 1–2 провайдеров + встроенный Assistant + открытая локальная модель для рутины. Помните: самая большая «потеря денег» — не токены, а **недели переделок** из-за ошибок в архитектуре и сохранениях. Лучше потратить на флагман час на проектирование, чем неделю на починку.

::::task easy Маршрутизатор (чистый Lua)
Напишите `routeTask(kind)`, возвращающую класс модели: `"format"` → `"tool"`, `"boilerplate"` → `"B"`, `"feature"` → `"A"`, `"architecture"` или `"security-review"` → `"S"`, `"bulk"` → `"L"`, иначе `"A"`.

:::starter
```lua
local function routeTask(kind)
end
```
:::
:::test
```lua
assert(routeTask("format") == "tool")
assert(routeTask("boilerplate") == "B")
assert(routeTask("feature") == "A")
assert(routeTask("architecture") == "S")
assert(routeTask("security-review") == "S")
assert(routeTask("bulk") == "L")
assert(routeTask("unknown") == "A")
```
:::
:::answer
```lua
local ROUTES = {
  format = "tool",
  boilerplate = "B",
  feature = "A",
  architecture = "S",
  ["security-review"] = "S",
  bulk = "L",
}

local function routeTask(kind)
  return ROUTES[kind] or "A"
end
```
:::

::::task mid Оценка стоимости (чистый Lua)
Напишите `estimateCost(inputTokens, outputTokens, pricePerMIn, pricePerMOut)` — стоимость в долларах (цены за миллион токенов). Пример: 200 000 входных и 20 000 выходных при $3/$15 = `0.6 + 0.3 = 0.9`.

:::starter
```lua
local function estimateCost(inputTokens, outputTokens, pricePerMIn, pricePerMOut)
end
```
:::
:::test
```lua
assert(math.abs(estimateCost(200000, 20000, 3, 15) - 0.9) < 1e-9)
assert(estimateCost(0, 0, 3, 15) == 0)
assert(math.abs(estimateCost(1000000, 0, 1, 5) - 1) < 1e-9)
```
:::
:::answer
```lua
local function estimateCost(inputTokens, outputTokens, pricePerMIn, pricePerMOut)
  return inputTokens / 1e6 * pricePerMIn + outputTokens / 1e6 * pricePerMOut
end
```
:::
