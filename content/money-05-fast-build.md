Цель — не «клонировать игры конвейером», а **быстро проверять идеи** и вкладываться в те, что показывают удержание. Скорость итераций — главное конкурентное преимущество малой команды.

## Принцип: один «движок» — много игр

Большинство симуляторов/коллекционных игр состоят из одних и тех же систем. Соберите их **один раз** как переиспользуемые модули с конфигами:

| Модуль | Что делает | Настраивается конфигом |
|---|---|---|
| **DataService** | загрузка/сохранение, сессии, миграции | схема данных, имя хранилища |
| **CurrencyService** | валюты, добавление/списание, события | список валют, иконки |
| **UpgradeService** | апгрейды по формуле | `UpgradesConfig` (база, множитель, макс. уровень) |
| **RebirthService** | ребёрты, бонусы | стоимость/бонусы |
| **ZoneService** | зоны/миры, открытие | `ZonesConfig` |
| **PetService / ItemService** | коллекции, экипировка | `PetsConfig`, шансы, редкость |
| **EggService / LootService** | рандомные награды с раскрытием шансов | таблицы весов |
| **ShopService** | passes/products, ProcessReceipt | `ProductsConfig` |
| **QuestService / DailyService** | задания, ежедневные награды | `QuestsConfig` |
| **EventService** | ивенты по таймеру | расписание |
| **LeaderboardService** | топы | категории |
| **UIKit** | кнопки, окна, числа, анимации | тема/цвета |
| **AudioService / FXService** | звуки, частицы | список звуков |
| **AnalyticsService** | события экономики/воронки | список событий |
| **AdminService** | серверные команды для вас | список админов |

Новая игра = **те же модули + новые конфиги + новый арт и тема**. Это сокращает «технический» этап с недель до дней, а силы уходят на то, что реально отличает игру.

:::money Экономия
Если один раз вложиться в качественный «каркас» (2–3 месяца, 1–2 человека + ИИ), каждая следующая игра обходится в 3–6 раз дешевле по времени. Но **не копируйте чужие игры** — делайте свою тему, UX и контент.
:::

## Структура репозитория-шаблона

```text
game-template/
├─ src/
│  ├─ server/
│  │  ├─ Main.server.luau
│  │  └─ Services/ (DataService, CurrencyService, …)
│  ├─ client/
│  │  ├─ Main.client.luau
│  │  └─ Controllers/ (UIController, InputController, …)
│  └─ shared/
│     ├─ Config/  (CurrenciesConfig, ZonesConfig, PetsConfig, ProductsConfig, …)
│     ├─ Types.luau
│     └─ Util/
├─ docs/ (ARCHITECTURE.md, SERVICES.md, RELEASE.md, decisions.md)
├─ AGENTS.md
├─ default.project.json  rokit.toml  wally.toml  selene.toml  stylua.toml
└─ .github/workflows/check.yml
```

Каждая новая игра: **fork/template-копия** → смена `Config/*` → арт → контент.

## План MVP за 2–4 недели

| Неделя | Цель | Результат |
|---|---|---|
| **0 (1–2 дня)** | Идея, ниша, 1 страница ТЗ, прототипы референса | Решение «делаем/нет» |
| **1** | Core loop + 1 зона + базовые апгрейды + сохранение | Играбельно за 5 минут |
| **2** | Мета-цикл (ребёрт/коллекция), магазин (2–3 продукта), UI-полировка, звук/эффекты | Проходится 1 час без скуки |
| **3** | Туториал (первые 2 минуты), мобильная адаптация, аналитика, баг-фиксы | Плейтест с 10–20 людьми |
| **4** | Иконка, миниатюры, описание, публикация, первые посты; план обновлений | Запуск и сбор метрик |

**Критерий остановки:** если после 1–2 недель плейтеста D1 < 15% и никто не хочет «ещё раз» — меняйте идею, а не раздувайте контент.

## Что делает человек, а что ИИ

| Этап | Человек | ИИ |
|---|---|---|
| Идея и нише | выбирает, оценивает конкурентов | помогает со списками, сравнением, вопросами |
| Геймдизайн цикла | решает, что приятно | генерирует варианты, формулы баланса, симуляции |
| Архитектура | утверждает | предлагает схему модулей/данных (сильная модель) |
| Код модулей | ревью, интеграция | основной объём (агент) |
| UI/UX | макет, вкус | реализация, идеи анимаций |
| Арт | стиль, отбор | генерация иконок/текстур |
| Баланс | решения, плейтесты | таблицы, симуляции |
| Тесты | сценарии | тест-кейсы, автотесты логики |
| Тексты/локализация | редакция | перевод/варианты |
| Публикация | запускает | чек-листы |
| Анализ | выводы | сводки метрик, гипотезы |

## Экономия токенов в «конвейере»

1. **Один раз** — сильная модель пишет `ARCHITECTURE.md` и `SERVICES.md` (контракты). Затем агент-исполнитель читает только их (десятки строк, а не весь код).
2. **Контракты вместо контекста:** `Types.luau` + сигнатуры сервисов — все модули опираются на них.
3. **Шаблон-генерация:** для нового контента («добавь 10 питомцев») просите **только конфиг** — код не меняется.
4. **Генерация по схемам:** формат конфигов закреплён типом + валидатором; ИИ не может «выдумать» поле.
5. **Пакетная работа:** тексты/переводы — batch-режим провайдера (дешевле).
6. **Тесты логики без Studio:** экономика, шансы, миграции — запускаются локально за секунды, без токенов.
7. **Агент с ограничением области:** «работай только в `src/server/Services/EggService.luau` и `Config/Eggs.luau`».
8. **Короткие сессии:** одна задача — одна сессия; итог — коммит.

## Контроль качества, чтобы скорость не убила игру

| Проверка | Как |
|---|---|
| Игровой цикл «весело?» | плейтест с 5 новичками, не друзьями |
| Мобильность | реальный телефон, ≥ 30 FPS |
| Сохранения | тест выход/перезаход/закрытие сервера |
| Безопасность | чек-лист из раздела ИИ |
| Правила | чек-лист соответствия |
| Метрики | D1/D7, время сессии, воронка покупок |

## Типичные ловушки «быстрой разработки»

- **Скорость вместо идеи:** клон без своей фишки теряется среди сотен.
- **Контент вместо цикла:** 50 питомцев не спасут скучный цикл.
- **Игнорирование мобильных:** большая часть аудитории потеряна.
- **Отсутствие аналитики:** вы не знаете, почему игроки уходят.
- **Раздутые обновления:** лучше малые частые обновления, чем один «большой взрыв».
- **«Деньги раньше любви»:** монетизация до того, как игрок увлёкся.

## Задания

::::task easy Конфиг вместо кода
Опишите (чистый Lua) конфиг `PetsConfig` на 3 питомца и функцию `getPets(rarity)`, возвращающую имена питомцев нужной редкости. Идея: новый питомец — это новая строка в конфиге, не изменение кода.

:::starter
```lua
local PetsConfig = {
  {id = "Dog", rarity = "Common", power = 1},
  {id = "Cat", rarity = "Common", power = 2},
  {id = "Dragon", rarity = "Epic", power = 50},
}

local function getPets(rarity)
end
```
:::
:::test
```lua
local c = getPets("Common")
assert(#c == 2 and c[1] == "Dog" and c[2] == "Cat")
assert(#getPets("Epic") == 1 and getPets("Epic")[1] == "Dragon")
assert(#getPets("Mythic") == 0)
```
:::
:::answer
```lua
local function getPets(rarity)
  local result = {}
  for _, pet in ipairs(PetsConfig) do
    if pet.rarity == rarity then
      table.insert(result, pet.id)
    end
  end
  return result
end
```
:::

::::task mid Валидатор конфига (чистый Lua)
Напишите `validateConfig(list)`: проверяет, что у каждого элемента есть строковые `id` и `rarity`, числовой `power > 0`, все `id` уникальны. Вернуть `true` или `false, "описание"`.

:::starter
```lua
local function validateConfig(list)
end
```
:::
:::test
```lua
assert(validateConfig({{id = "A", rarity = "Common", power = 1}}) == true)
local ok, why = validateConfig({{id = "A", rarity = "Common", power = 1}, {id = "A", rarity = "Rare", power = 2}})
assert(ok == false and why:find("A", 1, true))
ok, why = validateConfig({{id = "B", rarity = "Rare", power = 0}})
assert(ok == false)
ok, why = validateConfig({{id = 5, rarity = "Rare", power = 1}})
assert(ok == false)
```
:::
:::answer
```lua
local function validateConfig(list)
  local seen = {}
  for i, item in ipairs(list) do
    if type(item.id) ~= "string" or type(item.rarity) ~= "string" then
      return false, "элемент " .. i .. ": id и rarity должны быть строками"
    end
    if type(item.power) ~= "number" or item.power <= 0 then
      return false, "элемент " .. item.id .. ": power должен быть > 0"
    end
    if seen[item.id] then
      return false, "дубликат id: " .. item.id
    end
    seen[item.id] = true
  end
  return true
end
```
Такой валидатор запускают в CI — и ИИ не сможет «молча» сломать конфиг.
:::
