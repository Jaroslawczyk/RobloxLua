## Универсум и плейсы

- **Experience (вселенная, Universe)** — «игра» целиком с настройками, монетизацией, ID вселенной.
- **Place** — отдельная карта внутри Experience (стартовый плейс, лобби, арена и т.д.).
- Идентификаторы: `game.GameId` (universe), `game.PlaceId`, `game.JobId` (конкретный сервер).

## Публикация

1. **File → Publish to Roblox** — первый раз создайте Experience (название, описание, жанр, устройства).
2. Дальнейшие изменения: **Publish to Roblox** (перезаписывает *опубликованную версию*).
3. Для проверки используйте **Version History**: можно откатиться на прошлую версию.
4. Настройте в **Creator Hub → Experience → Settings**: Access (приватно/публично), Devices (ПК, телефон, планшет, консоль, VR), Max Players, Servers, Privacy, **Age guidelines (опросник по возрасту/контенту)**, Monetization, Localization, Security (API Services, HTTP).

:::warn Возрастной рейтинг и правила
Перед публичным запуском обязательно заполните опросник по содержимому игры (Experience Guidelines / maturity). Игры с неверными ответами могут быть закрыты. Следуйте [Roblox Community Standards](https://en.help.roblox.com/hc/en-us/articles/203313410-Roblox-Community-Standards) и политикам по монетизации. Для платных случайных предметов нужны вероятности — см. [[money-04-ethics-compliance]].
:::

## Тестирование перед релизом

| Режим | Когда |
|---|---|
| **Play (F5)** | быстрая проверка |
| **Test → Local Server (N игроков)** | репликация, Remote, сохранения |
| **Team Test** | с друзьями в реальном времени |
| **Опубликованная тестовая игра (Staging)** | отдельная Experience для проверки обновлений: закрытая, но с теми же скриптами |

Совет: держите **два Experience** — `MyGame (Dev)` и `MyGame` (продакшн). Правки сначала в Dev, потом переносите (Open Cloud/Rojo).

## Обновления без простоя

- При публикации новой версии **уже запущенные серверы продолжают работать на старой версии** до перезапуска.
- Принудительный перезапуск серверов делается из Creator Hub (отдельное действие «выключить серверы»; название и расположение меняются — проверяйте актуальный интерфейс). Для «живых» игр лучше **постепенный** перезапуск с объявлением игрокам.
- Для плавных обновлений делайте **обратно-совместимые** изменения данных (миграции схемы).
- **MessagingService** — отправить предупреждение всем серверам: `«Обновление через 5 минут, сохраните прогресс»`.
- Фичи включайте **флагами**: таблица `FeatureFlags` (DataStore/атрибуты), чтобы выключить сломавшуюся функцию без релиза.

## Метрики и аналитика

В **Creator Hub → Analytics**: пользователи (DAU/MAU), доход, удержание (D1/D7/D30), время сессии, платящие, воронки, платформы, страны, отчёты по ошибкам.

| Метрика | Что показывает | Ориентир (грубо) |
|---|---|---|
| D1 retention | вернулись на следующий день | «норма» ≈ 15–30%, хорошо > 30% |
| D7 retention | через неделю | > 8–10% |
| Avg session time | глубина вовлечения | 15+ мин для хорошей игры |
| Payer conversion | доля платящих | 1–5% |
| ARPDAU | доход на активного пользователя в день | зависит от жанра |
| Crash/error rate | стабильность | стремится к 0 |

(Цифры — ориентиры из опыта сообщества, не официальные нормативы; используйте свои фактические данные.)

## Open Cloud и автоматизация

**Open Cloud** — HTTP-API Roblox для автоматизации: публикация плейса, DataStore, MessagingService, Ordered/Memory Stores, подписи, лицензирование ассетов.

1. Creator Hub → **Credentials** → создать **API Key** с минимальными правами (например, `universe-places:write`) и ограничением по IP/Experience.
2. Храните ключ как **секрет** (GitHub Secrets), никогда не коммитьте в репозиторий.
3. Публикация плейса: загрузка `.rbxl` в `universes/{universeId}/places/{placeId}/versions?versionType=Published` с заголовком `x-api-key`. Готовые инструменты: `rbxcloud`, `mantle`, `lune`-скрипты, GitHub Action'ы.

Это основа CI/CD: пуш в ветку `main` → сборка Rojo → публикация в Dev/Prod.

## Безопасность аккаунта и игры

- Включите **2-Step Verification** на аккаунте владельца и всех админов.
- Для командных проектов используйте **Group** (группа владеет Experience) — а не личный аккаунт. Права по ролям: `Edit`, `Publish`, `Manage Monetization`.
- **Не доверяйте модели из Toolbox** слепо: проверяйте скрипты внутри на `require(число)` / скрытые бэкдоры.
- Отключите `HttpService`, пока он не нужен; не включайте `LoadStringEnabled`.
- Админ-панели — по проверке `UserId`/роли группы **на сервере**.
- Резервные копии: регулярно **Save to File** (`.rbxl`) и история в Git.

## Модерация и правила

- Все тексты (чат, имена) фильтруются автоматически через `TextService:FilterStringAsync` / `TextChatService` — для пользовательского текста **обязательно**.
- Контент (картинки, аудио) загружаемый вами проходит модерацию; следите за политикой авторских прав и аудио.
- Следите за обновлениями политик: раздел Announcements на DevForum и страницы политик в Creator Hub.

::::task mid Постепенное включение функции (чистый Lua)
Напишите `isEnabled(flag, userId, percent)`: детерминированно определяет, включена ли функция для пользователя при раскатке на `percent`% (0–100). Один и тот же `userId` всегда получает один результат; распределение примерно равномерное. Используйте остаток от деления `userId % 100 < percent`.

:::starter
```lua
local function isEnabled(flag, userId, percent)
end
```
:::
:::test
```lua
assert(isEnabled("NewShop", 150, 100) == true)
assert(isEnabled("NewShop", 150, 0) == false)
assert(isEnabled("NewShop", 5, 10) == true)
assert(isEnabled("NewShop", 55, 10) == false)
local on = 0
for id = 1, 1000 do if isEnabled("F", id, 30) then on += 1 end end
assert(on == 300, "on=" .. on)
```
:::
:::answer
```lua
local function isEnabled(flag, userId, percent)
  return userId % 100 < percent
end
```
Для разных флагов добавляют «соль» (хэш от `flag .. userId`), чтобы одни и те же пользователи не всегда попадали в тестовую группу.
:::
