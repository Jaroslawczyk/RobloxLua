## Воронка проекта: стадии и «ворота»

Каждая стадия заканчивается **воротами** (gate): вы идёте дальше только если выполнены критерии. Так вы не вкладываете месяцы в идею, которая не работает.

| Стадия | Цель | Срок | Ворота (критерии) |
|---|---|---|---|
| **0. Идея и исследование** | выбрать нишу и концепт | 2–5 дней | понятный цикл; 3 конкурента изучены; есть «своя» фишка |
| **1. Прототип** | проверить цикл «весело ли» | 1–2 недели | 5 тестеров играют > 10 мин без просьб |
| **2. MVP** | играбельная версия с сохранением | 2–4 недели | D1 на тестерах ≥ 25% (на малой выборке — ориентир), нет потери данных |
| **3. Soft launch** | публичный запуск малой аудитории | 2–4 недели | D1 ≥ 20–25%, D7 ≥ 7–10%, средняя сессия ≥ 12 мин, нет критических багов |
| **4. Рост** | масштабировать трафик | 1–3 месяца | LTV > CPI × 1.5; метрики не падают при росте |
| **5. Live-ops** | стабильное развитие | постоянно | регулярные обновления, стабильный доход, команда справляется |
| **6. Расширение** | новые игры/платформы/команда | по результатам | прибыль покрывает 2+ проекта/зарплаты |

:::tip Правило остановки
Если на воротах 2–3 метрики стабильно ниже порога после 2 итераций — **закрывайте или кардинально меняйте идею**. Сэкономленное время вложите в следующий эксперимент.
:::

## Технический продакшен — чек-лист

| Область | Что должно быть |
|---|---|
| **Сохранения** | сессионная блокировка, ретраи, миграции, BindToClose, тесты на перезаход |
| **Безопасность** | серверная валидация Remote, rate limit, идемпотентный ProcessReceipt, нет секретов на клиенте |
| **Производительность** | ≥ 30 FPS на среднем телефоне, нет утечек памяти, время загрузки < 15 с |
| **Мобильность** | UI проверен на разных экранах; кнопки ≥ 44 px |
| **Мониторинг** | аналитика, логи ошибок, алерты экономики |
| **Релизы** | CI, Dev/Prod окружения, откат, заметки к версии |
| **Документация** | README, архитектура, правила для ИИ, чек-листы |
| **Правила** | возрастной опросник, шансы опубликованы, фильтрация текста, лицензии |
| **Поддержка** | форма баг-репортов, Discord, ответы за 24 часа |

## Финансовый «продакшен»

1. **Группа Roblox** — владелец игры; роли и выплаты.
2. **Налоговый режим** выбран и оформлен (см. [[biz-02-poland-taxes]]).
3. **Учёт**: таблица доходов/расходов, хранение выписок DevEx, подписки, реклама.
4. **Резерв на налоги**: 25–35% каждого вывода.
5. **Бюджет проекта**: ИИ-подписки, реклама, ассеты, ПО — лимиты на месяц.
6. **Юридические документы**: соглашение между партнёрами, политика конфиденциальности (если собираете внешние данные), правила сообщества.

## KPI по стадиям

```lua run
-- простой «светофор» метрик
local function trafficLight(d1, d7, session, payers)
  local score = 0
  if d1 >= 0.25 then score += 1 end
  if d7 >= 0.08 then score += 1 end
  if session >= 12 then score += 1 end
  if payers >= 0.01 then score += 1 end
  if score >= 4 then return "зелёный: можно расти"
  elseif score >= 2 then return "жёлтый: итерации"
  end
  return "красный: пересмотреть идею"
end
print(trafficLight(0.31, 0.09, 14, 0.02))
print(trafficLight(0.18, 0.05, 9, 0.004))
print(trafficLight(0.12, 0.02, 5, 0.0))
```

## Риски и как ими управлять

| Риск | Последствие | Снижение |
|---|---|---|
| **Потеря данных игроков** | возвраты, репутация | тесты DataStore, блокировка сессий, бэкапы |
| **Эксплойты/дюпы** | инфляция, уход игроков | серверные проверки, журнал, быстрый откат |
| **Нарушение правил** | удаление игры/блокировка | регулярно читать политики, чек-лист соответствия |
| **Тренд ушёл** | падение онлайна | диверсификация, быстрые обновления, новая игра |
| **Конкуренты-клоны** | потеря аудитории | своё комьюнити, быстрые обновления, бренд |
| **Уход ключевого человека** | остановка | документация, права доступа, соглашение |
| **Выгорание** | потеря темпа | ритм, перерывы, разделение ролей |
| **Налоговые ошибки** | штрафы | бухгалтер, резерв, календарь платежей |
| **Зависимость от платформы** | изменения правил/комиссий | диверсификация (другие платформы/каналы) |

## Масштабирование

- **Увеличить количество проектов** (портфель из 2–3 игр) — но только когда процессы стабильны.
- **Нанять фрилансеров** на конкретные задачи (арт, звук, UI): чёткие ТЗ, договоры, проверка лицензий.
- **Локализация** (en/ru/pl/es/pt/…): значительно расширяет аудиторию.
- **Кросс-промо** между своими играми.
- **Своё комьюнити** (Discord/группа) — независимый канал.

## Когда проект «успешен»

Определите заранее личные цели:
- «Хобби-доход»: $100–500/мес. (покрывает расходы и немного сверху).
- «Подработка»: $500–2 000/мес. (стабильный параллельный доход).
- «Основной доход»: ≥ 2–3× ваших ежемесячных расходов **минимум 3–6 месяцев подряд** + резерв.

:::warn Не увольняйтесь рано
Доходы от игр волатильны. Правило безопасности: резерв на 6–12 месяцев расходов и стабильный доход проекта несколько месяцев подряд, прежде чем отказываться от основной работы/учёбы.
:::

::::task mid Срок окупаемости (чистый Lua)
Напишите `paybackMonths(initialInvestment, monthlyRevenue, monthlyCosts)` — через сколько месяцев вложения окупятся (округлить вверх). Если месячная прибыль ≤ 0 — вернуть `math.huge`.

:::starter
```lua
local function paybackMonths(initialInvestment, monthlyRevenue, monthlyCosts)
end
```
:::
:::test
```lua
assert(paybackMonths(1000, 600, 100) == 2)
assert(paybackMonths(1000, 300, 100) == 5)
assert(paybackMonths(1000, 100, 100) == math.huge)
assert(paybackMonths(0, 100, 50) == 0)
```
:::
:::answer
```lua
local function paybackMonths(initialInvestment, monthlyRevenue, monthlyCosts)
  local profit = monthlyRevenue - monthlyCosts
  if profit <= 0 then
    return math.huge
  end
  return math.ceil(initialInvestment / profit)
end
```
